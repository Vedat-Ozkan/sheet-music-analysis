# Research notes, 2026-10-01

Background research behind the revised plan (`docs/plan.md`). Three strands: engine and rendering, Anthropic distribution, OpenAI distribution.

Labels: **V** = primary source read on 2026-10-01. **U** = search snippet, secondary source or memory. **I** = inference. Re-check anything marked U or I before relying on it.

## 1. Engine and rendering

### Harmony models

| Model | Exact RN accuracy | Status |
|---|---|---|
| AugmentedNet | 0.464 | MIT. Last release v1.9.1 (Dec 2022), pins TensorFlow 2.5. Runs on TF 2.21 + tf_keras with patches (tested in the earlier session). No ONNX or PyTorch port found (U). |
| ChordGNN | 0.518 | MIT. Archived read-only 2026-06-11 (V). Weights on W&B. |
| AnalysisGNN | 0.530 | MIT code, no weights licence stated. `pip install -e .` from a clone, no PyPI package. Needs PyTorch, Lightning, PyG, partitura, `pyg-lib`. Weights only on W&B. README "under construction", 10 commits (V, github.com/manoskary/analysisgnn). Outputs: cadences, phrases, sections, pedal points, local/tonicized key, degree, inversion, quality, bass, root, non-chord tones. |
| RNBert | 0.574 | MIT. HF port `malcolmsailor/musicbert_hf`, weights `msailor/rnbert_weights`. **Input is MIDI**, not MusicXML. ~100M parameters (U). |
| RNHybrid | 0.576 | arXiv 2607.13587 (2026-07-15, V). MusicBERT encoder + AnalysisGNN-style graph network, 20+ tasks. Code points to the analysisgnn repo. Demo at analysisgnn.com shows top-3 candidates and partial-label completion. |

- BACHI: not found.
- Training-data licences: When in Rome new content CC BY-SA 4.0 (V, github.com/MarkGotham/When-in-Rome). DCML corpora CC BY-NC-SA 4.0 (U). Whether trained weights inherit these terms is unsettled (I).
- AugmentedNet without TensorFlow: tf2onnx `from_keras` breaks on TF ≥2.16 / Keras 3 (tensorflow-onnx #2348), converts GRU to a Loop graph (#1684), and has Bidirectional GRU errors (#802) (all U). Safer: convert once in a pinned old environment, or re-implement the Conv1D + dense + BiGRU forward pass in numpy from the 0.8 MB HDF5 (I).
- onnxruntime 1.30.0 (2026-09-10): Python ≥3.11, wheels 14–24 MB (V, PyPI).

### How good are LLMs alone?

- Musical Score Understanding Benchmark (arXiv 2511.20697 v4, 2026-04, V): chord and harmony level about 38% from text (ABC), about 30% from images; overall 49% text vs 24% images.
- Pond & Fujinaga (arXiv 2503.22853, V): RCM Level 6 questions; best with in-context teaching was Claude + MEI at 75%. MEI beat MusicXML, ABC and Humdrum as an encoding.
- LessWrong, "Testing LLMs on Undergraduate Music Theory" (2026-07-30, V, blog): 2026 models 75–100% on isolated chord spelling.
- CSyMR-Bench (arXiv 2601.11556, U): a tool-augmented agent beats a raw LLM.
- Conclusion (I): the LLM is a credible reviewer and explainer, not a sole labeller. Give it a compact per-beat table or MEI, plus model candidates.

### Rendering stack

- Verovio 6.3.0 (2026-08-19, V, PyPI): LGPL-3.0-only, Python ≥3.10, wheels for Windows, macOS, Linux glibc (no musllinux). Useful options (V, book.verovio.org): `svgBoundingBoxes`, `svgContentBoundingBoxes`, `svgViewBox`, `svgHtml5`, `svgCss`, `xmlIdSeed`, `xmlIdChecksum` (repeatable IDs), `mmOutput`, `breaks`. MusicXML importer improved in 6.0, 6.1 and 6.3.
- Labels: MusicXML `<harmony><numeral>` imports to MEI `<harm>`; `<function>` is deprecated since MusicXML 4.0 (V, w3.org). For full control inject MEI `<harm>`/`<fb>` after `getMEI()` (I).
- SVG to PNG: `resvg_py` 0.5.0 (2026-08-24, V), wheels for every platform, PNG only. Text fonts may need Verovio's `--font-text-liberation` or an explicit font file (I, untested).
- Avoid CairoSVG (needs system cairo) and PyMuPDF (drops `<style>` CSS, U). PDF: wrap PNGs with img2pdf or Pillow.
- music21 10.5.0 (2026-06-17, V): BSD-3, Python ≥3.11, wheel 20 MB. Reads `.mxl` natively (U). `chordify` is slow on large scores (U).

### Jazz and PDF input (v2)

- US public domain since 2026-01-01 (V, cspd.law.duke.edu/publicdomainday/2026): works from 1930, including "I Got Rhythm", "Body and Soul", "Georgia on My Mind", "Embraceable You", "But Not for Me", "On the Sunny Side of the Street". Fake-book arrangements may still be protected; write own lead sheets.
- No dedicated ii–V / tritone-sub library found (U). Weimar Jazz Database is ODbL, solos not lead sheets (U).
- OMR: homr 0.7.0 (2026-06-26, U), Audiveris 5.10.2 (Java, AGPL, U), LEGATO 2 (arXiv 2607.05769, V, no weights announced), Soundslice API (U). Multimodal LLMs are not reliable enough alone.

### Prior art

- **Second Ear** (second-ear.app, V): free, no signup, MusicXML or PDF via OMR, music21 rule-based Roman numerals under each beat, key-region brackets, coloured noteheads, AI explainer. Closest competitor.
- Harmonia (github.com/Yintercept94/harmonia, V): AugmentedNet + Verovio 6.2, static pages, reports 46% exact accuracy.
- music21-mcp-server (V): 13 tools incl. Roman numerals and cadences, no annotated rendering. MUSESCORE-MCP (U).
- Anthropic's MCP Apps examples include a "Sheet Music" server (ABC rendering with playback) (V).

## 2. Anthropic distribution

Most pages undated; Directory Policy dated 2026-04-15, two support articles 2026-08-06.

- **One directory**, managed at https://claude.ai/directory/manage (V, claude.com/docs/directory/publish). Pro, Max, or a Team/Enterprise owner can submit; Free cannot. The old form at platform.claude.com/plugins/submit "is no longer supported".
- **Plugin submission** (V, claude.com/docs/plugins/submit): GitHub repo (public before going live); steps Source → Validate → Listing → Data handling → Compliance → Submit. Automated validation and security scan on every version; human review for a new listing; no published turnaround. Listings track a branch or tag and re-scan each commit; bump `version` each release.
- `anthropics/claude-plugins-community` is a read-only nightly mirror; CLI install is still `name@claude-community`. `claude-plugins-official` takes no portal submissions (V).
- **Surfaces** (V, claude.com/docs/plugins/platform-support): skills load in Chat (web, desktop, mobile), Cowork and Claude Code. Remote MCP servers work in Chat once connected; local MCP servers, agents and hooks are ignored in Chat. A top-level `bin/` makes the plugin uninstallable in Chat and Cowork. Browsing under Customize > Plugins > Discover on paid plans.
- **Plugin limits** (V, pre-submission checklist): repo under 50 MiB archived / 256 MiB unpacked, each file under 5 MiB or validation stops; non-image files over 256 KiB and any binary other than images and fonts are held for a reviewer. README of at least 40 words and a licence are required. `npx`/`uvx` launchers must pin an exact version.
- **Skills** cannot be listed alone; bundle them in a plugin. Any plan can upload a skill ZIP under Customize > Skills (V, support article 12512180). Description up to 1,024 characters; SKILL.md under 500 lines. "The description is the only part Claude reads before deciding to load the skill."
- **Connectors** (V, claude.com/docs/connectors/building/review-criteria and /index):
  - Same portal. Listed as Community by default; Verified is assigned by Anthropic.
  - Every tool needs a `title` and `readOnlyHint` or `destructiveHint`; names ≤64 characters.
  - No auth is allowed. Transport is Streamable HTTP.
  - Tool results: text and images; about 150,000 characters per result and 240 s per call on claude.ai and Desktop; 25,000 tokens in Claude Code.
  - **Not accepted:** connectors that generate images with AI models. Diagram and chart tools are allowed.
  - Custom (unlisted) connectors work on all plans; Free gets one.
  - **No documented way for a connector to receive a chat attachment (U).**
- **Suggested Connectors** (V, claude.com/docs/connectors/building/directory-vs-custom): "Claude can recommend your connector in-chat when it's relevant to the user's task." Directory connectors only. Ranking "is usage-based". No equivalent found for plugins or skills (U).
- **Policy** (V, support article 13145358): privacy policy link if data is collected or a remote service is used; verified contact; no ads; "must not collect extraneous conversation data, even for logging purposes."
- **Metrics** (V, claude.com/docs/connectors/building/after-publishing): Usage tab with installs, active accounts, retention, runs per skill and MCP server, error rates, listing funnel; 90 days; CSV export.
- **Sandbox** (V, support article 12111783): code execution with network on by default for Free, Pro, Max; allowed domains include PyPI and GitHub; Team/Enterprise default to network off. 30 MB per file. Limits unpublished. `pip install music21 verovio` should work (I, untested).
- **Tools:** `claude plugin validate --strict` (the portal runs more checks), `claude plugin eval`, MCP Inspector.

## 3. OpenAI distribution

help.openai.com, chatgpt.com and Reddit blocked fetching, so claims from them are U.

- **Rename:** on 2026-07-09 ChatGPT "apps" became **plugins**; one Plugin Directory serves ChatGPT and Codex (U, secondary; docs now say "plugins", V, developers.openai.com/plugins).
- **Submission** (V, developers.openai.com/plugins/deploy/submission.md and plugin-guidelines.md): verified individuals or organizations; upload plugin ZIP; domain proof at `/.well-known/openai-apps-challenge`; one MCP server per plugin; **5 positive and 3 negative test cases, a video walkthrough**, release notes; four URLs (website, support, privacy, terms); name and short description ≤30 characters each. Content must suit ages 13–17. Review turnaround not documented.
- **UI is optional** (V, developers.openai.com/plugins/build/chatgpt-ui.md): "Keep the MCP tools useful without a component."
- **Files in** (V, plugins/reference.md): declare `_meta["openai/fileParams"]`; ChatGPT passes `{download_url, file_id, mime_type?, file_name?}`. One GitHub issue reports the parameter missing on about 10% of calls (U, openai-apps-sdk-examples #237).
- **Images out:** community thread of 2026-09-22/24 reports base64 PNG tool results often do not render; about 3 KB sometimes works, 3 MB fails; no official fix (V, community.openai.com/t/1399928).
- **Discovery:** Plugins tab, `@` invocation (V, learn.chatgpt.com/docs/plugins.md). In-chat suggestions and "enhanced distribution" for selected plugins (U for suggestions; V for the enhanced-distribution wording). Tool selection is driven by metadata; write descriptions as "Use this when…" (V, plugins/guides/optimize-metadata.md).
- **Metrics:** no publisher analytics (V, community.openai.com/t/1394612, unanswered request of 2026-09-03).
- **Custom GPTs retire 2026-12-11** (U, help article 20001519 snippet plus secondary coverage). Actions do not migrate.
- **Python sandbox** (V, simonwillison.net/2026/Jan/26/chatgpt-containers): outbound network blocked; `pip install` works through an internal PyPI mirror.
- **Skills:** bundled skills work in Chat and Work on web, desktop and mobile (V, learn.chatgpt.com/docs/build-skills.md). Plugin format: `plugin.json`, `skills/<name>/SKILL.md`, `mcp.json`. Marketplaces: `$REPO/.agents/plugins/marketplace.json`, `~/.agents/plugins/marketplace.json`, legacy `.claude-plugin/marketplace.json` (V, developers.openai.com/codex/plugins/build).
- **Claude-plugin conversion** (V, plugins/guides/submit-claude-plugin.md): portal converts `.claude-plugin/plugin.json`; SKILL.md kept; `.mcp.json` and `userConfig` dropped.
- **MCP server requirements** (V, plugins/build/mcp-server.md): Streamable HTTP over HTTPS; `noauth` allowed; `readOnlyHint`, `destructiveHint`, `openWorldHint` required; widget CSP lists `connectDomains`, `resourceDomains`, `frameDomains`.
- **Hosting:** Cloud Run free tier 180k vCPU-seconds/month (U). Fly.io small always-on machine about $5–6/month (U).
- **Go-to-market:** no case studies with per-tool numbers found. Tens to low hundreds of users a month without featured placement is an unsupported guess (I).

## Addendum, same day: AnalysisGNN weights

Found while installing, all verified directly:

- The W&B artifact `melkisedeath/AnalysisGNN/model-uvj2ddun:v1` returns "the provided API key cannot access this resource" for a normal logged-in account; the author's other W&B project is not visible either.
- The author's Hugging Face Space `manoskary/analysisgnn` (public, card says `license: mit`, last modified 2026-05-06, currently in build error) contains `checkpoint/model.ckpt` (126.9 MB, 13.5M parameters, HybridGNN, 60 epochs). It loads with `analysisgnn` main plus `graphmuse` from GitHub main; the PyPI graphmuse 0.0.5 wheel fails with `HybridGNN.__init__() got an unexpected keyword argument 'metadata'`.
- Upstream issue #9 (closed 2026-05-13) quotes the author by email: "the last public version is effectively deprecated. There should soon be a much better version, including an open-source Hugging Face model checkpoint, but because this is tied to an ongoing review process, it may take a while".
- `manoskary/analysisgnn-hybrid` on Hugging Face holds the newer RNHybrid checkpoints. It is publicly downloadable but its README calls it a "private bundle" and it has no licence; not used.
- Outputs of the working checkpoint: cadence, local and tonicized key, chord quality, inversion, root, bass, primary and secondary degree, harmonic rhythm, pitch-class set, phrase, section, pitch-in-chord (non-chord tones), pedal point, downbeat, note degree.
- Measured on the Chopin nocturne (1,246 notes): 4.5 s wall clock and 0.8 GB peak memory on CPU, including model load.
